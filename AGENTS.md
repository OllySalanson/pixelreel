# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Commands: `npm test` (node --test), `npm run lint` (ESLint), `npm start` (local server on :8000), `npm run check [reel] [-- --recorded]` (validates reels without a browser; CI runs it with `--recorded`). No build step; the browser loads `src/*.js` as ES modules directly.
- A reel is `reels/<name>/reel.js` (code allowed) or `reel.json` (data only, `src/format.js`, checked strictly and never run); `scripts/reel-file.mjs` finds either for the tools.
- `skill/pixel-reel.zip` (the Claude skill) and its unzipped copy in `plugins/pixel-reel/skills/` (the Claude Code plugin) are generated from `skill/pixel-reel/`, `index.html`, `src/` and the font by `npm run skill`, and committed; `test/onepage.test.js` fails until it is remade after any player change. `scripts/bundle.mjs` joins `src/` modules for one-file pages and only takes one-line `import { a } from './x.js';` and exported functions, classes, consts and lets.
- `npm run video` draws frames in Node with `@napi-rs/canvas` (a dev dependency) and the real kit on the player's clock (`scripts/video.mjs`), so the MP4 matches the player; it needs ffmpeg, and `test/video.test.js` skips without either.
- `service/` is the hosted connector (`npm run service`, docs/service.md): stateless MCP over Streamable HTTP plus `/r/<id>` pages; jobs reuse `scripts/voices.mjs` and `scripts/video.mjs` on a checked-out folder, so `test/service.test.js` injects a fake recorder, video maker and card drawer (`service/card.mjs` draws each reel's picture for link previews). It runs on Cloud Run with reels in a bucket (`S3Store`, `PIXELREEL_S3_*`); docs/deploy.md has the project, settings and redeploy command. The image's ffmpeg is Debian's 5.1, older than most dev machines', so video changes can pass locally and fail there.
- What Claude is told (`service/mcp.mjs`: tool descriptions, the `make_reel` schema, `formatGuide`, the results) decides how good a connector reel is, so try a change with a real session, not just the tests (docs/service.md, "What Claude is told"). `service/pacing.mjs` times each recorded reel's pictures to its voice, so a kept reel differs from the one sent. No test runs the one-page player in a page (`src/main.js`, `service/app-bridge.js`), so after changing either, watch it: `node scripts/chat-stand-in.mjs` shows the player as a chat does. A reel can be played while it is still being recorded: `play.json` hands out the lines so far and `playable` (`service/ahead.mjs`), and the one-page player takes late lines through `window.pixelreelClips` (docs/service.md, "Playing while it records"). `npm run service` keeps one Python with the voice model loaded (`service/voice.mjs`, about 1 GB, and about 450 MB more for each other language it has loaded, two at most; `PIXELREEL_WARM_VOICE=0` turns it off).
- The website (pixelreel.pro) is `site/`, put together by `service/site.mjs` and served by `service/static.mjs`, which serves only addresses matching its rules; docs/site/README.md has the design rules (built for dyslexic readers) and the design log, and `scripts/site-fit.js` checks a page's layout in a browser at every Make it comfy setting, which no test can; it cannot see inside a dialog, rules for mouse users or the printed page ("Changing it" there says how to look). Its pages may hold no inline styles or scripts (the content security policy blocks them), its scripts import the player's modules by relative path so Node can test them, and `site/art/` is drawn by `npm run site-art`. The site's QR codes are made on the server by `site/js/qr.js` (`{{scan}}`, `{{scanthis}}` in a page). The reels it plays are `reel.json` reels in `reels/`, so changing a section's words means changing and re-recording its reel. The form that makes a reel has a page of its own, `/make` (`site/pages/make.html`, `site/js/maker.js`). `PIXELREEL_TRY=1` switches on Make it right here (`service/writer.mjs` asks the Claude API to write a reel for a visitor from words, a link, writing, a PDF or a picture; it costs money, so it is off by default, and its tests use a stand-in). The limits on what a visitor may give live in `site/js/given.js`, which the page and the service both read. `/try` answers at once with a reel that is still being written (`Reels.begin`), and Claude writes it after the response, so its tests wait on `server.written()` before `reels.idle()`. Where the service offers other narrators the home page has a card for each (`narratorsHtml` in `service/site.mjs`), and each narrator's hello is a one-scene reel in their own voice (`reels/voice-<name>`, recorded with `--voice`). The site is an installable app: `site/js/sw.js` (served as `/sw.js`, a plain script, not a module) keeps pages, files and recordings for when there is no internet, always asking the service first, so a kept copy never hides a change, `site/js/kept.js` keeps a made reel there only when someone asks, and `site/js/shared.js` hands the make-one box what a phone shares to `/share`; `test/app.test.js` runs it with stand-ins, and docs/site/README.md ("On a phone's home screen") says how to try it for real.
- Timing and state live in `src/player.js` and `src/narrator.js`, drawing in `src/kit.js`, `src/pictures.js` and `src/transitions.js`, all DOM-free so `test/` drives them with mocked timers and the recording context in `test/fake-canvas.js`. Only `src/main.js` (the player page) and `src/export.js` (the banner maker) touch the page.
- node's `mock.timers` counts a timer set inside a callback from the end of the current `tick()`, so tests tick to one timer boundary at a time.
- Clips are matched to scenes by their exact `say` text through `audio/manifest.json`, not by position. Editing a scene's words makes it fall back to the browser voice until `npm run voices <reel>` is rerun, and CI (`npm run check -- --recorded`, `test/reel.test.js`) fails until it is. Clip files named as 16-hex-digit hashes are made by the tool; any other name is a hand-made recording that `voices` never replaces or deletes.
- Pocket TTS also reads French, German, Spanish, Italian, Portuguese and Dutch (`npm run voices <reel> -- --lang french`; in the service, `PIXELREEL_LANGUAGES`), and other narrators can be asked for (`PIXELREEL_NARRATORS`). Both are on in the image, which builds the models in (`Dockerfile`), and off from a checkout unless set: docs/service.md, "Other languages" and "Other narrators". They were checked by speech-to-text only; nobody who speaks the languages has listened. The player's own words in each language (buttons, "Press Play", the wait in a chat) are `src/words.js`, used by the player in a chat and by any reel whose `reel.json` names its `language` (as the skill's do); nobody who speaks them has read those either, and a reel's own page (`site/`) is still in English.
- New reels record with Pocket TTS (`peter_yearsley`); the committed showreel and example reel are Kokoro `bm_george`, which `npm run voices` keeps because a reel keeps the narrator its manifest names, so re-recording them needs `scripts/setup-voices.sh kokoro` (see docs/voices.md). Keep committed audio small (mono 48k) and record in one batch.
- The showreel (`reels/showreel/reel.js`) is the player page's default reel (`index.html`) and the README's source: its gags are timed to `CUES` taken from the recorded clips, and `docs/readme/README.md` lists the banner maker settings that remake the README's animated pictures. Changing a scene's words means re-recording, re-timing its cues, and remaking any picture that shows it.
- To check pictures by eye, `?reel=<name>&scene=N&t=S` holds one frame; for many frames, draw them with `createKit` on a canvas of your own rather than timing screenshots of the live player.
- House style for all text: plain dash, never an em dash (`test/hygiene.test.js` enforces it).
